# CursorFence B 站视频制作方案

这是一条面向双屏用户、窗口化游戏玩家和远程桌面用户的产品演示视频。核心目标不是把所有设置讲完，而是让观众在几秒内看懂一个具体痛点，并在一次真实演示后记住 CursorFence 的解决方式。

建议成片长度为 3 分 30 秒到 4 分 30 秒，横屏 16:9，1440p 或 1080p，60 fps。视频采用“真实录屏为主、少量 AI 画面负责气氛和转场”的方式。涉及程序实际行为的画面全部使用真实录制，避免 AI 生成出不存在的按钮、设置或运行结果。

## 视频定位

一句话定位：

> 一个按快捷键就能把鼠标留在当前窗口或当前显示器里的轻量 Windows 工具。

这条视频需要主动说明 CursorFence 属于已有的“鼠标边界锁定”工具类别。可以提到 cursorlock 等替代品，表达方式应当是“这个需求早就有人解决过，但使用中仍有一些痛点；CursorFence 针对这些痛点做了更稳定、更容易判断状态、更方便发布的实现”，不要暗示 CursorFence 是整个类别的发明者，也不要贬低其他项目。

主要受众：

- 双屏或多屏办公，经常把鼠标滑到旁边屏幕的人；
- 窗口化或无边框游戏中，鼠标容易跑出窗口的人；
- 使用远程桌面、录屏或演示软件，需要控制鼠标范围的人；
- 想要一个绿色、便携、开源 Windows 小工具的人。

## 完整旁白与镜头脚本

下面的台词按约 150–170 字/分钟设计。剪辑时可以根据语速删掉括号里的可选句。

### 0:00–0:12：冷开场

画面：先录一段真实的双屏桌面。把一个窗口放在主屏，鼠标快速滑向右侧副屏，出现“点错、焦点丢失或游戏视角异常”的结果。画面不要出现过多桌面隐私，必要时打码任务栏里的应用名称。

旁白：

> 双屏用户应该都遇到过这个瞬间：鼠标只是想点一下窗口边缘，结果直接飞到旁边的屏幕。窗口化游戏、远程桌面和录屏时尤其明显。

字幕：

> 鼠标又跑到旁边屏幕了？

### 0:12–0:35：先给结果

画面：切到 CursorFence 主界面。鼠标放在目标窗口，按一次 `ScrollLock`，状态点变绿，通知出现，鼠标尝试越过边界但停在边缘；再次按下后解除。保留真实的按键音或轻微提示音。

旁白：

> CursorFence 做的事情很简单：按一次快捷键，把鼠标锁在当前窗口，或者锁在当前显示器的可用工作区；再按一次，马上解除。默认快捷键是 ScrollLock。

字幕：

> 一次锁定 · 再按解除

### 0:35–0:55：背景与差异

画面：显示 cursorlock 或“同类工具”字样的简洁文字卡，不要长时间展示其他项目界面，也不要做未经授权的对比截图。随后回到 CursorFence 的 GitHub 页面。

旁白：

> 这个需求并不新，cursorlock 之类的工具已经证明它有实际需求。CursorFence 也不是重新发明这个类别，而是把使用中经常遇到的几个问题集中处理：混合 DPI 和多显示器边界、锁定状态不够直观、快捷键偶尔失效，以及发布后用户不知道该下载哪个文件。

### 0:55–1:35：窗口模式

画面：打开一个浏览器或记事本作为安全演示目标，避免使用有反作弊的在线游戏。选择“当前窗口”，把鼠标移动到窗口四边，展示窗口移动或缩放后边界跟随。可以用屏幕录制软件的放大框突出鼠标位置。

旁白：

> 先看窗口模式。把鼠标放到目标窗口上，按 ScrollLock，锁定范围会以按键瞬间的前台窗口为目标。窗口移动或缩放后，边界会跟着窗口变化。关闭锁定后，鼠标恢复正常移动。

字幕：

> 当前窗口：适合窗口化应用、远程桌面、录屏

### 1:35–2:05：显示器模式

画面：使用两块分辨率不同、最好带一点缩放差异的显示器。选择“当前显示器”，锁定后把鼠标推到屏幕底部和侧边。明确展示：鼠标可以到工作区最底部，但不会进入任务栏；然后尝试推向副屏，光标停在当前屏边缘。

旁白：

> 如果你想让整块屏幕都能用，就切换到显示器模式。CursorFence 会在激活的瞬间捕获鼠标所在的那块显示器，并使用 Windows 的工作区边界。这样可以到工作区最底部，但不会卡进任务栏；也不会因为鼠标靠近边缘，就突然把目标换成另一块屏幕。

字幕：

> 显示器模式：包含工作区，不包含任务栏

### 2:05–2:40：设置与 ScrollLock 设计

画面：快速打开设置区域，按顺序展示：录制快捷键、窗口/显示器模式、通知开关、开机启动、启动时自动锁定。最后特写真实键盘的 ScrollLock 指示灯：关闭同步、开启同步各演示一次。若键盘没有 ScrollLock 灯，用 UI 状态点替代，不要伪造灯光。

旁白：

> 设置部分保持简单，但该有的自定义都有。快捷键可以重新录制，支持 Ctrl、Alt、Shift、Win 加主键；锁定范围可以在窗口和显示器之间切换；通知默认打开，也可以关闭；还可以选择当前用户开机启动。
>
> ScrollLock 是这里一个很有意思的设计。它现在很少被主动使用，但很多键盘还保留着指示灯，所以它既不容易误触，又能帮助你确认状态。打开同步后，灯亮代表已锁定，灯灭代表已解除。CapsLock 和 NumLock 也能使用类似逻辑，不过程序会先提醒它们仍然承担原本的系统功能。

### 2:40–3:10：原理与鼠标硬件

画面：用简洁动画表现一个矩形边界，鼠标在矩形内移动；切入代码局部或 GitHub README 的“How it works”段落。代码只展示关键 API 名称，不要让观众停留在难懂的实现细节上。

旁白：

> 原理其实很克制。CursorFence 调用 Windows 原生的 `ClipCursor`，给系统光标设置一个矩形范围。窗口模式读取前台窗口的位置，显示器模式读取当前显示器的工作区。程序不会移动鼠标，不会模拟鼠标输入，也不修改 DPI、回报率、加速度、按键或滚轮行为，更不需要安装鼠标驱动。

字幕：

> Windows 原生 ClipCursor · 不改鼠标硬件参数

### 3:10–3:35：反作弊边界

画面：使用一张简单的“普通桌面 / 在线竞技游戏”分栏卡片。不要展示具体游戏品牌的反作弊告警，也不要声称“绝对安全”。

旁白：

> 需要说明的是，任何工具都不能替你保证所有游戏的反作弊策略。CursorFence 不注入游戏进程、不读游戏内存，但它仍然会调用系统的光标限制接口。普通桌面、多屏办公、远程桌面和单机游戏更适合使用；竞技游戏或严格反作弊环境，建议先退出工具再启动游戏。

### 3:35–4:05：开源与下载

画面：真实打开 GitHub 仓库，展示 README 中英文入口、Releases 页面和 `CursorFence-Portable-windows-x64.zip`、`CursorFence-Installer.exe`。便携版解压后运行 `CursorFence-Portable.exe`；安装版按向导安装后从开始菜单启动。

旁白：

> 项目已经开源在 GitHub，Windows 用户不需要安装 Python。到 Releases 下载便携 ZIP 或 `CursorFence-Installer.exe`。便携版是单文件，安装版会注册到 Windows 的已安装应用列表，并使用目录型程序保持稳定启动。

字幕：

> GitHub：Rhongomiant1227/CursorFence

### 4:05–4:20：收束与互动

画面：回到绿色激活状态的主界面，配合鼠标停在窗口边缘的特写。最后定格 GitHub 地址和评论问题。

旁白：

> 如果你也经常被多屏鼠标跑偏打断，可以试试 CursorFence。你更常用窗口模式，还是显示器模式？如果遇到边界、快捷键或兼容性问题，欢迎在评论区和 GitHub Issue 里告诉我。

字幕：

> 你会把鼠标锁在哪个范围？

## 真人录制清单

这些内容必须用真实录屏，因为它们是产品承诺的一部分：

1. 未锁定时鼠标可以跨屏移动；
2. 按 `ScrollLock` 后状态点变绿、通知出现、鼠标停在边界；
3. 再次按键解除；
4. 窗口模式跟随窗口移动或缩放；
5. 显示器模式允许到工作区底边，但避开任务栏；
6. 不同分辨率或混合缩放的多显示器布局；
7. 快捷键录制、模式选择、通知开关和开机启动设置；
8. ScrollLock 指示灯同步（只有实际键盘支持时才录）；
9. GitHub README、Release 页面和 ZIP 文件结构；
10. 软件版本号与最终下载链接。

录制建议：

- 使用 OBS，录制 1440p/60 fps；如果桌面是 4K，可以录 4K 后在剪辑软件中裁切关键区域；
- 鼠标指针使用较大的高对比度样式，点击时增加短暂的圆环或缩放；
- 录制前关闭无关通知、聊天软件和敏感窗口；
- 先录“失败场景”，再录“解决场景”，两段使用同一桌面布局，方便剪辑做前后对照；
- Windows 通知停留时间可能受系统设置影响，视频中只需要展示它出现，不要把具体停留秒数当作卖点；
- 在显示器模式镜头中，任务栏必须可见一小段，观众才能看懂“到工作区底边但不到任务栏”的差别。

## Minimax H3 可以负责的部分

如果本地部署 Minimax H3，建议把它用在不需要证明真实软件行为的素材上。提示词中明确要求“无文字、无品牌 UI、无可识别软件界面”，再在剪辑软件里叠加真实字幕。

适合交给 H3 的素材：

- 2–3 秒的抽象开场：发光的鼠标轨迹从主屏越界到副屏，随后被一条柔和边界拦住；
- 多显示器桌面的氛围镜头：两块屏幕、鼠标光点、边界线，作为真人录屏之间的转场；
- 一个简洁的矩形边界动画，用来解释 `ClipCursor` 的“系统光标范围”概念；
- ScrollLock 键帽和键盘指示灯的特写，作为概念性 B-roll；
- 结尾的抽象“边界稳定、光标回到工作区”镜头。

不适合交给 H3 的素材：

- CursorFence 主界面、设置页、通知内容；
- GitHub 仓库、Release 下载页和文件名；
- ScrollLock 实际切换前后的键盘灯状态；
- 鼠标是否真的停在任务栏上方、窗口移动后边界是否跟随；
- 任何需要观众据此判断功能是否工作的镜头。

可直接尝试的 H3 提示词：

> 16:9 horizontal video, 3 seconds, cinematic but minimal desktop technology abstract. Two monitors on a dark desk, a small white mouse cursor trail moves toward the edge of the right monitor, a thin blue boundary softly stops the trail, subtle green status glow appears. No text, no logos, no brand UI, no realistic app windows, no people, smooth camera motion, clean dark navy and teal palette.

如果生成结果出现乱码文字、虚构按钮或不稳定的鼠标形状，直接舍弃，不要修补后当成真实功能展示。AI 素材在成片中的建议占比控制在 10% 到 20%，其余由真实录屏、旁白和字幕完成。

## 剪辑与声音

整体节奏应当快：前 35 秒内必须完成“问题出现—按键—锁定成功”的闭环。每个功能镜头只保留一个动作，设置页采用快速推近和鼠标轨迹，不要逐项朗读所有文字。

声音建议使用三层：

- 人声：清楚、偏近讲解，优先保证可懂度；
- 操作声：ScrollLock 按键、通知出现、鼠标移动，各自轻微即可；
- 背景音乐：低存在感的电子氛围音乐，旁白开始时自动压低 6–9 dB。

不要使用夸张的“系统破解”“游戏外挂”音效，也不要把锁定动作剪成像修改鼠标硬件或注入游戏的视觉效果。
